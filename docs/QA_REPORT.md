## 1. Smoke-чек

Запускается одной командой (хард-гейт):

```powershell
npm test
```

Сейчас 4 теста:

1. `GET /login` отдаёт 200 и форму входа.
2. `GET /` без сессии → 302 на `/login`.
3. `GET /clients` без сессии → 302 на `/login`.
4. `POST /login` с неверными кредами → 200 и сообщение «Неверный логин или пароль».

Источник: [tests/smoke.test.js](../tests/smoke.test.js).

## 2. Чек-лист ручного regression

> Простое описание страниц с матрицей доступа и пустыми пунктами «Что менять» — в [PAGES.md](PAGES.md). Этот раздел — пошаговый regression-чек.

### 2.1 Авторизация
- [ ] Вход `owner/owner123` → `/`, полная панель и финансовые KPI на дашборде (при дефолтной матрице).
- [ ] Вход `admin/admin123` → `/`, операционная CRM: услуги/допы/аналитика/клиенты/брони есть; **нет** пользователей, журнала, настроек, матрицы, финмодуля (403 по прямым URL).
- [ ] Прямой переход без права на `/admin/settings` или `/admin/finance` → 403.
- [ ] Выход из системы → попадаем на `/login`, повторное `GET /` → 302 на `/login`.
- [ ] Неактивный пользователь (`is_active=0`) не может войти → «Неверный логин или пароль».

### 2.1a Smoke по матрице ролей (быстрая сверка)

Минимальный набор для подтверждения, что описанные в [PAGES.md](PAGES.md) и [SECURITY.md](SECURITY.md) §4a гейты реально работают.

#### Под `owner` (владелец)

- [ ] В сайдбаре полный блок администрирования (по матрице): Услуги, Доп. услуги, Финансы, Аналитика, Пользователи, Журнал, Настройки, при необходимости матрица доступов.
- [ ] На главной видны агрегаты «Всего клиентов», «Выручка за день» и суммы в календаре месяца.
- [ ] Открываются: `/admin/finance`, `/admin/users`, `/admin/logs`, `/admin/settings` и т.д.
- [ ] CSV-экспорты отчётов и финансов работают (UTF-8 BOM, `;`).

#### Под `admin` (администратор парка)

- [ ] Видны: Клиенты, Бронирования, Услуги, Доп. услуги, Аналитика, учёт времени (по флагам), мой кабинет; кнопки «Расход»/«Смена» и блок «Мои записи за сегодня» на дашборде.
- [ ] **Нет** финансовых KPI на главной (как у владельца).
- [ ] Прямой `GET /admin/settings`, `/admin/users`, `/admin/logs`, `/admin/finance`, `/admin/access` → **403**.
- [ ] Полный CRUD клиентов и броней (при дефолтной матрице).
- [ ] `POST /admin/demo-preview` при включённом демо — **200** (вместе с `owner`).

#### Линейный персонал (`instructor` / `cleaner`)

- [ ] `GET /bookings` → 200; `GET /bookings/new` → **403**.
- [ ] На дашборде нет блока `#dashboard-quick` (нет фоновых вызовов `/quick`).
- [ ] `GET /me/...` при наличии `me:shifts` → 200.

#### Быстрые действия (`/quick/*`) под `admin` парка

- [ ] Модалки «Расход»/«Смена», whitelist категорий, валидация времени смены — как раньше.
- [ ] Удаление: **своя** запись ≤1 ч → 200; чужая или старая → **403**. Под **`owner`** — удаление чужих записей разрешено.

#### Демо-режим предпросмотра ролей

- [ ] Под **`owner`** или **`admin`** (парк) включить в `/admin/settings` чекбокс «Демо-режим: предпросмотр ролей» и сохранить.
- [ ] В шапке панель «Предпросмотр как»; выбрать, например, **Инструктор**, «Применить».
- [ ] Сайдбар сужается под выбранную роль; в шапке бейдж демо-режима.
- [ ] У **`owner`** прямой `GET /admin/users` **открывается** (сервер смотрит на реальную роль и матрицу); пункт в сайдбаре при этом может быть скрыт из‑за `effectiveRole`.
- [ ] Выключение `demo_mode_enabled` сбрасывает `session.demoPreviewRole` — навигация возвращается к обычной.

### 2.2 Клиенты
- [ ] `GET /clients` отображает таблицу.
- [ ] Создание клиента: пустое ФИО → 400, корректные данные → редирект на карточку.
- [ ] Поиск по имени/телефону через поле в списке.
- [ ] Удаление клиента каскадно удаляет его брони (проверить, что на дашборде брони пропадают).

### 2.3 Услуги / Допы (admin)
- [ ] `GET /services` отображает три группы (беседки/лазертаг/квесты).
- [ ] Создание услуги без названия → 400.
- [ ] Toggle активности — услуга должна пропасть из формы брони, существующие брони на неё остаются.
- [ ] Допы — список + inline-CRUD работает.

### 2.4 Бронирования
- [ ] Форма `/bookings/new` подгружает услуги/допы/клиентов.
- [ ] Создание брони на 2 услуги (например, беседка + лазертаг) — обе появляются в карточке `/bookings/:id`.
- [ ] **Редактирование**: `/bookings/:id/edit` показывает уже выбранные услуги/допы (позиции восстановлены 1:1), селекты содержат каталоги услуг/допов.
- [ ] Конфликт: 2 брони на одну беседку с пересекающимися интервалами → 409 «Время пересекается с бронированием #N: …».
- [ ] Многочасовая бронь корректно отображается в сетке дашборда (одна карточка с rowspan).
- [ ] Смена статуса (`PATCH /:id/status`) обновляет карточку.
- [ ] Удаление брони убирает её с дашборда.

### 2.5 Бонусы / промо
- [ ] После создания платной брони у клиента увеличиваются `bonus_points.points` и `total_earned`.
- [ ] `GET /bookings/api/bonus/:clientId` возвращает корректный баланс.
- [ ] `GET /bookings/api/promo` возвращает текущие настройки.

### 2.6 Панель руководителя
- [ ] Аналитика: фильтры периода/категорий пересчитывают KPI и графики.
- [ ] CSV-экспорт `bookings`/`clients`/`finance` качается, открывается в Excel с правильной кириллицей (BOM присутствует).
- [ ] Создание/обновление/удаление пользователя пишет в `activity_logs`.
- [ ] Журнал: фильтрация по пользователю/действию/дате работает; «Очистить за N дней» удаляет старые записи.
- [ ] Настройки: сохранение → `?success=saved`, перезагрузка отображает обновлённые значения.

### 2.6a Финансы и предоплата (2026-05)

- [ ] `/admin/finance`: видны блоки «Оценочные начисления» (смены, 15% лазертаг и база — только по **полностью оплаченным** броням с лазертагом в позициях); переключение по ссылкам «Сводка / Оплаты / …» с любой подстраницы.
- [ ] `/admin/finance/payments/:id`: есть поднавигация и кнопка «К списку оплат».
- [ ] CSV `export?type=overview` содержит колонки `shift_accrual`, `lasertag_lines_subtotal`, `lasertag_instructor_estimate`.
- [ ] Новая бронь: «Частично» + обычная беседка — предоплата автозаполняется 1000 ₽ (или итог, если итог &lt; 1000); сохранение с другой суммой → ошибка.
- [ ] Бронь с услугой «Караоке» (или другой с режимом 50%) + «Частично» — предоплата ровно половина итога; 49% → ошибка.
- [ ] В `/services/:id/edit` у беседки доступен выбор режима предоплаты; у других категорий блок скрыт, на сервер уходит `default`.

### 2.7 Адаптив и таблицы (global layout sweep, 2026-05-06)

**Сделано в коде**

- [`public/css/style.css`](../public/css/style.css): объединён `.table-wrapper` — единый блок с `overflow-x: auto` (раньше второе определение задавало `overflow: hidden` и отменяло горизонтальный скролл для широких `.data-table` с `min-width: 720px`). У `.main-content` и `.content` добавлен `min-width: 0`, чтобы flex-колонка не резала вложенный скролл.
- [`views/clients/detail.ejs`](../views/clients/detail.ejs): таблицы «История бонусов» и «История бронирований» — класс `responsive-table` и атрибуты `data-label` на ячейках для режима «карточек» при `max-width: 768px` (как у остальных списков).
- Регрессия: [`tests/smoke.test.js`](../tests/smoke.test.js) — `GET /clients/:id` с бронью содержит `responsive-table` и `data-label`.

**Ручная проверка (чеклист по ширинам окна)**

- [ ] **~1280px:** дашборд с сайдбаром, `/bookings/:id` (сетка карточек + узкая колонка), `/admin/finance/*` с таблицами — таблицы в белой обёртке прокручиваются по горизонтали при необходимости, контент не обрезается без скролла.
- [ ] **~768px:** выдвижной сайдбар; списки с `responsive-table` — строки таблицы складываются в карточки с подписями из `data-label`.
- [ ] **~375px:** форма брони (`/bookings/new`), модалки «Новая запись» / «Расход» / «Смена» — кнопки и поля не вылезают за экран, модалка прокручивается при длинном содержимом.
- [ ] **`/?mode=day` на узкой ширине:** отображается **та же таблица расписания**, что на ПК; горизонтальный скролл, колонка времени остаётся видимой при прокрутке; подсказка про прокрутку вбок.
